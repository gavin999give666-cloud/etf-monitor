# GUI 暂停/中断功能与日志区域扩展

## 总体方案

采用**信号文件机制**实现暂停/继续和优雅中断：GUI 在输出目录创建 `.pause_flag` 或 `.stop_flag` 文件，子进程在每个 trial 开始前轮询检查。无新依赖，改动集中在 3 个文件。

## 修改范围

| 文件 | 改动类型 | 改动量 |
|------|---------|--------|
| `optimizer_gui.py` | GUI 按钮/布局/逻辑 | ~80行新增 |
| `run_search.py` | 主循环添加信号检查 | ~15行新增 |
| `param_optimizer.py` | 目标函数添加信号检查 | ~15行新增 |

**文件**: `F:\windows10桌面\量化\etf-monitor\V6.2.1\A500\run_search.py`

1. 添加 `--signal-dir` 命令行参数（argparse）

2. 在主搜索循环（`for idx, params in enumerate(all_combinations):`）的**每次迭代开始处**插入信号检查：
   ```python
   # 检查停止信号
   if args.signal_dir and os.path.exists(os.path.join(args.signal_dir, '.stop_flag')):
       print(f"\n[{datetime.now()}] 收到停止信号，保存当前结果后退出...")
       break
   # 检查暂停信号（阻塞等待）
   if args.signal_dir:
       while os.path.exists(os.path.join(args.signal_dir, '.pause_flag')):
           time.sleep(0.5)
   ```

## 风险与缓解

| 风险 | 缓解措施 |
|------|----------|
| 暂停时子进程 stdout 管道缓冲区满（64KB） | 子进程 print 使用 `flush=True`；或设置环境变量 `PYTHONUNBUFFERED=1` |
| 信号文件残留（进程崩溃后） | 启动时和退出时均清理 `.pause_flag` 和 `.stop_flag` |
| 日志超过万行导致 GUI 卡顿 | `log_message()` 中限制最大 8000 行，超限裁剪 |
| 优雅停止子进程不响应 | 10 秒超时后自动强制 `kill()` |
| Optuna 暂停时 trial 超时 | 暂停时间不计入 trial 的 timeout（Optuna 的 timeout 是基于实际计算时间） |

---

## 被拒绝的方案

| 方案 | 拒绝原因 |
|------|----------|
| psutil `process.suspend()/resume()` | 需要额外安装 psutil；在 Windows 上挂起子进程可能导致管道死锁 |
| stdin 管道通信 | 需要大幅修改子进程的输入处理逻辑，改动量大、风险高 |
| 共享内存/mmap | 过度复杂，跨进程同步问题多 |
