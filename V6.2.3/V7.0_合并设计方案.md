## 一、现状诊断（合并依据）

对 V6.2.3\科创 与 V6.2.3\A500 逐文件比对（MD5）：

| 维度 | 科创版 | A500版 | 合并结论 |
|------|--------|--------|---------|
| 策略引擎 20+ 模块（strategy/indicators/behavior/evidence 等） | 相同 | 相同 | 原样迁移 |
| config.py（378 行） | 仅参数值不同 | 仅参数值不同 | 各自优化参数 → 提取为独立 profile JSON |
| param_optimizer.py | 2268 行 | **3451 行**（自适应进程池/暂停停止信号/模式注册表） | **以 A500 版为基线** |
| data_updater.py | 516 行 | 481 行 | 逐 diff 择优合并 |
| backtest.py | 740 行 | 747 行 | 逐 diff 择优合并 |
| main.py / strategy.py / evaluation.py 等 | 差 1-2 行（STOCK_CODE 相关） | 同左 | 以 A500 版为基线 |

**核心约束**：全项目 25+ 模块以 `import config` 读全局常量，优化器通过 `setattr(config, ...)` 动态改参——天然"单进程单标的"。合并方案的进程隔离原则由此而来。

## 三、核心机制

### 3.1 Profile 激活式 config

```
config.activate_profile("589800")
  → 读 profiles\589800.json → setattr 到 config 模块全局
  → 同步派生值（STOCK_CODE、DB 路径、runs 路径）
```

两条铁律：
1. **主进程（GUI）同一时刻只激活一个标的**。切换标的 = 重新加载数据 + 重建策略实例（日线数据量小，成本可忽略）。
2. **所有重计算（优化/回测）在子进程跑**，子进程入口统一 `--profile {code}` 先激活自己。既避免参数串扰，也允许不同标的的优化并行（受全局 CPU 上限约束）。

放弃的备选方案：依赖注入式重构（把 25+ 文件的 `config.XXX` 改为传参）。改动量约 10 倍且每个标的需重新复现检验，风险收益不成比例。

### 3.2 参数生命周期

```
新标的 → _default.json 冷启动（GUI 标记"未优化"）
       → 数据更新（--update）→ 跑 param_optimizer（heavy 四阶段，独立 runs\{code}\）
       → Top-K 结果 → GUI 一键"应用"→ 写回 profiles\{code}.json
       （不再正则改写 config.py；优化器产物全部带标的维度，互不覆盖）
```

新标的需先积累足够历史数据（建议 ≥ 3 年日线）再跑 heavy 优化，GUI 在数据不足时提示。

## 四、GUI 设计（pywebview + WebView2）

- **技术栈**：pywebview（Windows 走 Edge WebView2）+ Vue3（vue.global.prod.js 本地内嵌）+ ECharts（本地内嵌）。无 node/npm 构建链，双击即用，完全离线。
- **通信**：前端 `window.pywebview.api.xxx()` → bridge.py。快操作（信号/数据查询）线程池直接执行；长任务（优化/回测）subprocess 子进程执行。
- **进度**：子进程写 `runs\{code}\status.json` + 日志文件，前端 2 秒轮询。控制（暂停/停止）复用现有 `.optimizer_pause.flag` / `.optimizer_stop.flag` 机制。
- **资源控制**：复用 A500 版 adaptive_pool 自适应进程池，GUI 提供 CPU 上限滑块，全局生效。

## 七、风险清单

1. **路径改造遗漏**（主要工作量）：优化器/数据层现有大量相对路径（checkpoint、db、cache 回退查找 V5.0/V4.0...），多标的并行时若不带标的维度会互相覆盖。P1 需全局路径审查，统一 Path 管理。
2. **data_updater/backtest 两版差异合并**：逐 diff 择优，P1 复现检验兜底。
3. **WebView2 runtime**：Win10 IoT LTSC 2021 一般自带 Edge；app 启动时检测，缺失则引导安装。
4. **新标的冷启动无优化参数**：_default.json + "未优化"标记，防止误以为默认参数即已优化。
5. **主进程激活切换的实例缓存**：V6Strategy/BehaviorMemory 等在构造时读取 config 值，切换标的必须重建，禁止跨标的复用实例。

## 八、验收后处置
