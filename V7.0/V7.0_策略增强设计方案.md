# V7.0 策略增强设计方案（P6 算法重构 → P5 优化体系）

> 定稿日期：2026-08-21。本方案为设计文档，未改任何代码。
> 决策人确认：① 仓位下限全放开到 0%；② 三层决策架构（L1 战略 / L2 战术 / L3 风控）；③ 风险目标 = 最大回撤 ≤ 基准一半且正超额；④ 执行顺序先 P6（算法重构）后 P5（优化体系+GUI），原"整体验收归档"顺延为 P7。

## 一、诊断定案：为什么策略 ≈ 基准

### 1.1 三个结构性根因（参数优化无法突破的天花板）

| # | 根因 | 代码证据 | 后果 |
|---|------|---------|------|
| 1 | **仓位被钳死在 [0.70, 0.95] 窄带** | `scoring_engine.py:185` `target = max(0.70, min(MAX_POSITION, target))`；初始仓位 0.89~0.95 | 策略本质是"永远八成仓的指数基金"，净值曲线必然贴合基准。择时贡献被压缩到 25 个百分点带宽内 |
| 2 | **Bull 行情下卖出信号被系统性废除** | `config.py:281` `Bull: sell_div=0.12` → 卖出分需 ~417 分才触发最低减仓，实际满分仅 100~150 | 高位永不主动止盈，589800 满仓扛出 -28.4% 回撤 |
| 3 | **优化目标与"跑赢基准"错位** | `param_optimizer.py:620/626` 年化收益 `*100` vs 超额收益 `*60`；heavy 路径 `*150` vs `*80` | 优化器在满仓结构里只会挑"绝对收益高"的参数，等价于挑选 beta |

### 1.2 回测实证（V6 基线，P6.1 将固化存档）

| 标的 | 区间 | 交易日 | 基准收益 | 策略收益 | 超额 | 最大回撤 | 交易数 | 平均持仓 |
|------|------|--------|---------|---------|------|---------|--------|---------|
| 589800 | 2025-03~2026-08 | 358 | +72.17% | +65.88% | **-6.28pp** | -28.4% | 6 | 43.3 天 |
| 563360 | 2024-10~2026-08 | 454 | +30.54% | +34.69% | +4.16pp | -13.09% | 12 | 22.8 天 |

358 个交易日仅 6 笔交易——"精准抓低位、高位止盈"在结构上就没有发生的机会。

### 1.3 能力盘点：闲置资产与真实短板

**闲置（P6 将激活）**：MACD/MACD_hist、ROC3/ROC5、VWAP/VWAP_dev、VolumeZ 已计算但无消费方；EmotionBuilder 的 PCA/ICA 融合默认关闭；CrowdPsychology 被 EmotionBuilder 架空。

**真实短板**：
- Regime 仅 Bull/Bear/Range 三态，无"高位过热 / 熊末恐慌"相位；
- 无硬止损、无主动止盈（唯一高位信号 RSI_Overbought 基础分仅 25，Bull 下 ≈ 3 分）；
- `MIN_HOLD_DAYS`（589800 为 34 天）锁仓与"及时止盈"直接冲突；
- 回测收益计算疑似未实际扣除 SLIPPAGE/COMMISSION（P6.1 核实）。

**结论：参数优化没有失效，是运行在天花板以下。先给策略行动空间（P6），优化才有意义（P5）。**

## 二、改造蓝图：三层决策架构

### 2.1 决策流

```
日线 OHLCV
  ├─ L1 战略层（新）：Regime 主态 + 相位开关(Overheat/BottomFishing) + 波动率目标
  │      → 输出：仓位中枢 center ∈ [0, 0.95]
  ├─ L2 战术层（现有引擎降级为"调节器"）：
  │      行为检测(9种) → 事件生命周期 → Evidence 四源融合 → Reward/Risk
  │      → 输出：偏移量 offset ∈ [-0.25, +0.20]
  ├─ 合成：target = clamp(center + offset, 0.0, MAX_POSITION)
  └─ L3 风控层（新，最高优先级）：硬止损 / 阶梯止盈 / 回撤熔断
         → 输出：仓位上限覆写 cap，target = min(target, cap)，立即执行
```

**核心思想：现有 25+ 模块全部保留，但从"唯一决策者"降级为"中枢附近的调节器"；仓位的大幅摆动交给 L1（趋势）和 L3（风险）负责。**

### 2.2 L1 战略层：仓位中枢

**Regime 主态不变**（Bull/Range/Bear，`regime_detector.py` 判定逻辑不动，避免 Replay/ML 三维键 `(Regime, Behavior, Psychology)` 稀疏化），**新增两个独立相位开关**（不进 Replay 键，只作中枢乘数）：

| 相位 | 检测条件（复用闲置指标） | 对中枢的作用 |
|------|------------------------|-------------|
| **Overheat 高位过热** | 距 60 日高点 <3% 且（MACD_hist 顶背离 或 放量滞涨(vol_ratio>1.3 且 ROC5 衰减) 或 VWAP_dev>2σ 持续 3 日）且情绪 ∈ {Euphoria, Exhaustion} | `center *= 0.5`（主动高位减仓通道，**不受 Bull sell_div 压制**） |
| **BottomFishing 熊末恐慌** | 情绪 ∈ {Panic} 且（PanicSell 或 DoubleBottom 事件 Confirmed）且 Volatility_percentile > 80 | `center += 0.15`（左侧分批建仓通道，允许在 Bear 中提前布局） |

现有 `near_ath_suppression`（strategy.py:304-323，仅抑制买入）改造并入 Overheat 相位，从"抑制买"升级为"主动卖"。

**仓位中枢表（初始默认值，进搜索空间由 P5 优化）**：

| Regime | center 默认 | band（offset 活动余量） |
|--------|------------|----------------------|
| Bull | 0.75 | ±0.20 |
| Range | 0.45 | ±0.25 |
| Bear | 0.15 | ±0.15 |

**波动率目标叠加**：`center *= min(1.0, TARGET_VOL / realized_vol_20d)`，TARGET_VOL 默认 0.20。高波动期自动降中枢，替代现在形同虚设的 volatility_risk 评分项。

### 2.3 L2 战术层：现有引擎 → offset 调节器

`score_to_target_position()`（scoring_engine.py:144-186）重写为两段映射：

| buy_score | offset |
|-----------|--------|
| ≥68 | +0.20 |
| ≥62 | +0.15 |
| ≥56 | +0.10 |
| ≥50 | +0.05 |

| sell_score | offset |
|------------|--------|
| ≥68 | -0.25 |
| ≥62 | -0.18 |
| ≥56 | -0.12 |
| ≥50 | -0.06 |

- `REGIME_WEIGHTS`（buy_mult/sell_div）**保留但作用域缩小**：只作用于 raw score 的放大/压缩，offset 有界后不再造成"卖出永不可达"的单边失衡；
- **低位通道**：BottomFishing 相位确认时 offset 上限临时 +0.15（允许越中枢加仓，抓恐慌低点）；
- **高位通道**：Overheat 相位确认时直接追加 -0.30 越中枢减仓；
- `SCORE_HOLD_ZONE`（±15 净评分持有区）保留，作用于 offset 而非绝对仓位；
- **初始仓位 0.95 → 由首日 Regime 的 center 决定**（消除"回测起点即满仓"的偏差）。

### 2.4 L3 风控层：新模块 `quant/risk_guard.py`

纯函数模块（输入：持仓状态 + 当日行情；输出：仓位上限 cap 与动作原因），**优先级高于一切评分信号，且不受 MIN_HOLD_DAYS / SCORE_HOLD_ZONE 限制**：

| 机制 | 规则（默认值进搜索空间） |
|------|------------------------|
| 硬止损 | 浮亏 ≥ -8% → 仓位减半；≥ -12% → 清仓。180 日冷静期计数，记录进 backtest_records |
| 阶梯止盈 | 浮盈 ≥ +15% → 减 1/3；≥ +25% → 再减 1/3；**距 60 日高点回撤 ≥ 4% → 清仓锁利**（高位及时止盈的主力机制） |
| 回撤熔断 | 策略净值自峰值回撤 ≥ 12% → 仓位上限强制 20%；解除条件：收盘站上 MA20 且连续 5 日确认 |

### 2.5 新旧架构对照

| 维度 | V6（现状） | V7（P6 后） |
|------|-----------|------------|
| 仓位范围 | [0.70, 0.95] | [0.00, 0.95] |
| 空仓可能 | 不可能 | Bear+熔断时常态 |
| 高位止盈 | RSI_Overbought(≈失效) | L3 阶梯止盈 + Overheat 相位（独立于 regime 压制） |
| 低位买点 | 4 种行为需严格确认 | 保留 + BottomFishing 左侧通道 |
| 止损 | 无 | L3 硬止损 |
| Regime 作用 | 全局乘数（可废掉卖出） | 只定中枢，不压制风险信号 |
| 现有引擎角色 | 唯一决策者 | 中枢调节器（全部保留） |

## 三、优化体系重设计（P5，服务新架构）

### 3.1 新目标函数 `benchmark_beating_objective`

```python
score  = excess_return * 150                          # 主目标：基准超额
       + dd_improvement * 80                          # dd_improvement = (bench_dd - strat_dd) / |bench_dd|
       - max(0, |strat_dd| - DD_TARGET) * 200         # 超风险目标重罚（DD_TARGET = 基准回撤的 50%）
       + min(sharpe * 8, 15)                          # 质量项
       - max(0, total_trades - TRADE_CAP) * 2         # 换手软约束（TRADE_CAP 默认 40）
# Walk-Forward 验证段 OOS excess ≤ 0 的参数组直接淘汰，不进 Top-K
```

`composite_objective` / `returns_aggressive_objective` 保留作为对照模式（optimizer_modes 注册表新增 `heavy-excess` / `light-excess` 模式，不删旧模式）。

### 3.2 搜索空间 v2

**新增（克制，共 11 个——两标的数据仅 358/454 天，参数越多过拟合越重）**：

| 参数 | 范围 |
|------|------|
| CENTER_BULL / CENTER_RANGE / CENTER_BEAR | 0.5-0.9 / 0.3-0.6 / 0.0-0.3 |
| TARGET_VOL | 0.15-0.30 |
| OVERHEAT_CENTER_MULT | 0.3-0.7 |
| BOTTOMFISHING_BOOST | 0.0-0.25 |
| STOP_LOSS_PCT / STOP_LOSS_HARD | -5%~-12% / -10%~-18% |
| TAKE_PROFIT_T1 / T2 | +10%~+20% / +18%~+30% |
| TRAIL_EXIT_DRAWDOWN | 3%-6%（距 60 日高点回撤清仓线） |

**移除出搜索空间**：`MAX_POSITION` 固定 0.95、`INITIAL_POSITION`（改由 center 推导）、`BULL_SELL_DIV` 等 6 个 regime 乘数缩域后敏感度下降，仅保留 `BULL_BUY_MULT`、`BEAR_BUY_MULT` 两个。

`POSITION_FLOOR` 作为 config 常量固定 0.0（不进搜索空间——它是架构决策不是可调参数）。

### 3.3 防过拟合纪律

1. walk-forward（复用现有 `run_walk_forward_validation`，n_splits=3）以 **OOS 超额** 为主指标；
2. OOS/IS 超额衰减 > 60% 的参数组拒绝写回 profile；
3. Top-20 参数做敏感度扰动（±10%），净值变化 > 30% 视为悬崖参数，弃用；
4. 新参数 11 个 + 保留旧参数约 20 个，总搜索空间 ≤ 32 维，与现有 heavy 基线持平；
5. 重优化先跑 light（两标的，管线 sanity），确认目标函数行为正常后再启动 heavy（563360 可从已迁移断点续算的机制外新起，589800 数据短建议只跑 light + 网格精修）。

### 3.4 GUI 优化页（原 P5 页面清单不变，新增两卡）

- **优化前诊断卡**：当前 profile 的仓位分布直方图、策略-基准日收益相关性、超额来源分解（择时/仓位/残差）——让"为什么优化没用"在 GUI 上可见；
- **参数版本对比卡**：V6 参数 vs V7 参数并排 diff（复用 --heavy-view 与参数页）。

## 六、风险清单

1. **样本太短是最大风险**：358/454 天数据 vs ~32 维搜索。对策：参数克制（新增仅 11 个）、WF 强制、OOS 门槛、悬崖参数筛查；绝不因 GUI 好用就放开参数量。
2. **过拟合新形态**：仓位自由度放大后，优化器可能学到"恰好躲过样本内每一次下跌"的参数。对策：3.3 纪律全项为硬门槛而非建议。
3. **踏空焦虑**：空仓期遇反弹（如 2025-09 式急涨）会跑输。对策：BottomFishing 左侧通道保证恐慌段有仓位；验收标准里"Bull 主升段低仓占比 < 30%"。
4. **V6 复现基线失效**：P6 后 --signal 与旧版不再一致（必然）。对策：baseline_v6.json 快照 + STRATEGY_MODE 开关 + 影子模式，旧基线永远可复算。
5. **Replay/ML 键稀疏**：相位不进 (Regime, Behavior, Psychology) 三维键，仅作乘数，行为统计连续性不受影响。
6. **MIN_HOLD_DAYS=34 与止盈止损冲突**：L3 信号豁免锁仓；MIN_HOLD_DAYS 本身降为 5-10 进搜索空间。
7. **交易成本放大**：交易数从 6 笔升到 ~20 笔，若成本未计入则回测虚高。P6.1 审计为第一优先级。
8. **heavy 时长**：参数维度持平但每 trial 回测更重（risk_guard 逐日计算）。light 先行验证管线，heavy 用现有断点/暂停机制。

## 七、远期展望（本方案不做，仅记录方向）

- **P8 多标的轮动**：V7.0 多标的架构的天然延伸——用 7 个预置标的的相对强弱（如科创系 vs 宽基的 20 日动量差）在标的间分配仓位，超额来源从"择时"扩展到"轮动"。需等 P6/P5 稳定、各标的均有优化 profile 后再评估。
- EmotionBuilder PCA 融合、CrowdPsychology 与 EmotionBuilder 的合并去重：属清理项，可在 P7 前顺手做，不阻塞主线。
