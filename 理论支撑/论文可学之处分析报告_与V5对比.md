## 一、论文一：MACD择时策略优化（郭凝，2022）

### 1.1 论文核心方法

```
MACD(DIF, DEA) + EMA
        ↓
   Random Forest（二分类：未来10日上涨/下跌）
        ↓
   趋势判断指标（UT↑ / DT↓）
        ↓
   过滤MACD金叉/死叉信号
```

**流程：**
- **MACD金叉**（DIF上穿DEA）→ 产生买入候选
- **RF预测未来10日上涨** → 确认信号有效 → **执行买入**
- **RF预测未来10日下跌** → 过滤假信号 → **不执行**

### 1.2 关键实验结果

| 指标 | 纯MACD (2019) | hMACD (2019) | 纯MACD (2021) | hMACD (2021) |
|------|:---:|:---:|:---:|:---:|
| 年化收益率 | 11.2% | **43.4%** | -11.7% | **1.6%** |
| 盈亏比 | 2.04 | **3.74** | 0.52 | 0.42 |
| 交易次数 | 27 | **4** | 19 | 3 |
| 最大回撤 | 175.90 | **21.08** | 633.43 | **185.33** |

**核心发现：hMACD大幅减少虚假信号（交易次数从27降到4），在牛市放大收益，在熊市减少亏损。**

### 1.3 V5.0 当前对应的机制

V5.0 的 Confidence 计算（[event_engine.py#L152-L227](file:///d:/windows10桌面/量化/V5.0/event_engine.py#L152)）：

```python
CONFIDENCE_BASE = 40           # ← 人工设定
CONFIDENCE_INCREMENT = 8       # ← 人工设定
CONFIDENCE_DECREMENT = 10      # ← 人工设定

# 证据评估（完全人工规则）：
# DoubleBottom 证据：
#   MA5拐头 → +1（人工权重）
#   成交量恢复 → +1（人工权重）
#   不创新低 → +1（人工权重）
#   创新低 → -2（人工权重）
# 
# 市场修正：
#   Bull市场买入 → +5
#   Bear市场买入 → -5
# 
# 情绪修正：
#   Panic/Fear买入 → +3
#   Euphoria买入 → -5
```

### 1.4 论文解决了V5.0的什么痛点？

| V5.0 痛点 | 论文如何解决 | 差距 |
|-----------|-------------|------|
| **Confidence是人工规则的加法器**，写死权重不可学习 | 用RF从历史数据学习特征权重，自动发现哪些因子重要 | 核心差距 |
| **Confidence输出是确定性分数（72分）**，不包含不确定性信息 | 输出**概率**（上涨82%），包含置信区间信息 | 范式差距 |
| **各因子权重没有数据验证**（MA加分=Volume加分） | RF自动分配特征重要性，差离值(DIF)被证明比DEA更有预测力 | 校准差距 |
| **无法量化"这个信号有多可靠"** | 概率本身可校准：预测80%时实际成功60%→校准后→调整策略 | 可用性差距 |
| **缺少多模型对比/验证机制** | RF vs SVR vs ANN系统对比，选择最优模型 | 方法论差距 |

### 1.5 对V6的核心启示

**启示 1：ML做过滤器，不是发生器。（最重要）**
- 论文的RF不替代MACD产生信号，而是过滤假信号
- V6也必须保持Behavior作为信号源（这是V5的核心资产），ML只做置信度判断
- 很多人看到ML会误以为：所有指标 → XGBoost → BUY，这种系统几乎不可解释

**启示 2：不同市场环境下，同一行为的成功率差异是ML真正应该学习的。**
- 论文的RF只输入了技术指标特征，但**遗漏了市场环境**
- 实际上：Bull + DoubleBottom成功率可能91%，Bear + DoubleBottom成功率可能仅38%
- RF/XGBoost的输入必须包含 Regime 特征，让模型学习到 **"行为 × 环境"的交互效应**，而非孤立地学习行为
- V6方向：`(Behavior, Regime, Emotion, 技术指标) → ML → P(up | Context)`

**启示 3：Confidence不应是分数，应是概率。**
- V5：`DoubleBottom → Confidence = 40 + 8 + 8 + 8 - 5 = 67分`
- 论文范式：`(DoubleBottom, Bull Market, ...) → RF预测 → 未来10日上涨概率 = 83%`
- V6方向：`Behavior特征向量 + 环境上下文 → ML模型 → P(未来N日上涨)`

**启示 4：因子权重应由数据决定，不是经验。**
- V5目前MA加分=Volume加分=RSI加分（等权重），但数据可能告诉我们：成交量因子对DoubleBottom确认的贡献远大于MA拐头，而且在熊市和牛市中各因子的重要性排序可能完全不同
- V6方向：模型自动学习条件化的因子重要性

## 二、论文二：投资者情绪综合指数（杜子金，2022）

### 2.1 论文核心方法

```
PE、换手率、成交量、成交额、PSY、封闭基金折价率、SHIBOR（7个指标）
        ↓
    Z-Score 标准化
        ↓
    主成分分析（PCA）→ 前3个主成分（累积贡献率87%）
        ↓
    SENT = 加权组合（F1×51% + F2×35% + F3×14%）
        ↓
    皮尔森检验 → SENT与上证50ETF价格正相关（r=0.240, p<0.001）
```

**策略：**
```
SENT的MA(6)上穿MA(24)  +  价格的MA(12)上穿MA(30)
        ↓
    双金叉确认 → BUY

任一条死叉 → SELL
```

### 2.2 关键实验结果

| 指标 | 样本内 (2017-2019) | 样本外 (2020-2021H1) |
|------|:---:|:---:|
| 累计收益率 | 41.8% | 22.1% |
| 年化收益率 | 13.92% | 14.73% |
| 最大回撤 | 4.68% | 7.41% |
| 胜率 | 62.5% | 45.5% |

同期上证50指数累计收益率仅13.19%，策略跑赢大盘。

### 2.3 V5.0 当前对应的机制

V5.0 的情绪引擎（[crowd_psychology.py#L69-L107](file:///d:/windows10桌面/量化/V5.0/crowd_psychology.py#L69)）：

```python
# 完全基于硬编码的Z-Score/RSI/ADX阈值
if z_score < -2.2:    target = Emotion.PANIC
elif z_score < -1.5:  target = Emotion.FEAR
elif z_score < -0.5:  target = Emotion.HOPE
elif z_score > 0.5:   target = Emotion.OPTIMISM
elif z_score > 1.5 and rsi > 65 and accel > 0:
                       target = Emotion.EUPHORIA
```

**问题：**
- 只用价格衍生指标（Z20、RSI、加速度、ADX），未使用任何**真实市场微观数据**
- 阈值完全人工设定（Z<-2.2→Panic），没有数据支撑
- 无法捕获"量价背离"（价格涨但成交量萎缩→情绪虚高）

### 2.4 论文解决了V5.0的什么痛点？

| V5.0 痛点 | 论文如何解决 | 差距 |
|-----------|-------------|------|
| **情绪判断只用价格数据**（Z20、RSI），信息源单一 | 用7个多维度市场指标（价、量、资金、利率）综合判断情绪 | 信息源维度的量级差距 |
| **情绪阈值全是人工设定**（Z<-2.2→Panic） | 降维算法自动提取主成分，阈值由数据分布决定，而非拍脑袋 | 客观性差距 |
| **情绪只有6个离散状态**，丢失连续信息 | SENT是连续值（如67.3），承载更丰富的情绪信息 | 信息密度差距 |
| **情绪状态切换需要2天确认**，滞后 | SENT每日计算，实时反映 | 时效性差距 |
| **缺少"价格+情绪共振"机制** | 双金叉确认（价格均线金叉 AND 情绪均线金叉） | 信号确认机制的差距 |

### 2.5 对V6的核心启示

**启示 1（最重要）：真正重要的不是PCA，而是多源数据融合。**

论文用了PCA，但PCA只是当时（2022年）的工具选择。论文的核心思想是：

```
价格 + 成交量 + 资金 + 融资 + ETF → Emotion
```

而不是：

```
Z-Score → PCA → Emotion
```

V6应该做一个 **EmotionBuilder**，支持多种融合算法作为后端，默认用PCA，但架构上允许：

| 算法 | 适用场景 | 特点 |
|------|------|------|
| PCA | 线性关系、可解释性要求高 | 经典、稳定、可解释 |
| AutoEncoder | 非线性关系 | 更深层的特征提取 |
| ICA | 独立信号源分离 | 分离情绪与噪声 |
| UMAP | 可视化 + 降维 | 保留局部结构 |
| LightGBM Feature Importance | 监督学习场景 | 直接学习情绪对收益的贡献 |
| Transformer Embedding | 时序依赖 | 捕捉情绪演进模式 |

**架构原则：EmotionBuilder 不要锁定在单一算法上。**

**启示 2：情绪指标应包含多维市场数据。**

论文的7个指标作为起点，V6可扩展为：
- 成交量/成交额
- 融资余额变化
- ETF资金净流入/流出
- 北向资金净流入/流出
- 涨跌停比
- 新高新低比
- 波动率指数（如中国波指）
- 期权Put/Call比率

**启示 3：价格+情绪双确认机制。**
- 论文：价格金叉 + 情绪金叉 → Buy
- V6对应：Behavior信号 + Emotion Improvement → 提升Confidence
- V5目前没有这个"双确认"逻辑——Behavior检测到DoubleBottom后，Emotion是否在改善不被单独检查

## 三、论文三：财经文本收益率方向预测（顾文涛，2020）

### 3.1 论文核心方法

```
新浪财经"股市及时雨"+"市场研究"（5万+篇新闻）
        ↓
    HowNet词典 + Loughran-McDonald金融词典（翻译+人工筛选）
        ↓
    Word2Vec训练词向量 → 余弦相似度扩充 → 财经新闻情感词典(FNSD)
        ↓
    每日情绪指数 SI = log((1+积极词数)/(1+消极词数))
        ↓
    时变加权密度模型(F-TVF)：情绪指数作为衰减因子
        ↓
    评分加权模型：组合Logistic + TVF + F-TVF
        ↓
    预测上证指数日收益率方向（涨/跌）
```

### 3.2 关键实验结果

| 模型 | 最佳准确率 | 对数评分 | 二次评分 |
|------|:---:|:---:|:---:|
| Logistic | 57% | -0.74 | 0.46 |
| TVF（无情绪） | 58% | -0.73 | 0.47 |
| F-TVF（有情绪） | 61% | -0.72 | 0.49 |
| 评分加权模型 | **64%** | **-0.69** | **0.50** |

情绪指数在1%水平上显著（回归系数0.971），加入情绪指数将准确率从58%提升到61%，评分加权进一步到64%。

### 3.3 V5.0 当前对应的机制

V5.0 目前**完全没有**文本/新闻分析模块。这是V5架构中的空白领域。

### 3.4 论文方法论的历史定位

| 论文方法（2020年） | 2026年替代方案 | 评价 |
|------|------|------|
| 金融领域情感词典构建 | 不需要——LLM内置了金融语义理解 | 已被替代 |
| Word2Vec训练词向量 | 不需要——LLM embedding已包含上下文 | 已被替代 |
| 每日情绪指数 SI = log((1+Np)/(1+Nn)) | Qwen/DeepSeek直接输出：`今天市场情绪：68` | 更简单且更准确 |
| 非参数时变密度模型 | 思想仍有价值（见启示1） | 方法论可借鉴 |
| 评分加权模型组合 | 可用于V6的Ensemble | 直接可用 |

**关键判断**：论文的文本分析Pipeline（爬虫→分词→词典→Word2Vec→情绪指数）在2026年已完全被LLM替代。不需要维护情感词典，不需要训练Word2Vec。
未来路径：

```
新华社 / 财联社 / 人民日报
        ↓
    Qwen / DeepSeek API
        ↓
    今日市场情绪：68（结构化输出）
```

### 3.5 对V6的核心启示

**启示 1：非参数思维。**
- 论文的F-TVF模型不需要假设收益率服从特定分布（Logistic模型需要假设Logistic分布）
- V5当前所有阈值和规则都是"参数化"的（手工设定），未来可以让部分模块非参数化
- 例如：不做"Z<-2.2→Panic"的硬编码，而是用核密度估计自适应确定当前市场环境的分位数阈值

**启示 2：多模型融合优于单模型。**
- 论文的评分加权模型（组合3个模型）在所有指标上都优于任一个单独模型
- V6如果引入ML，应考虑Ensemble方法（RF + XGBoost + LightGBM投票）而非单一模型

**启示 3：当前不做实现，但预留接口。**
- 论文证明财经新闻情绪对收益率有预测力（p<1%），但A500 ETF场景下资金面信号 >> 新闻信号
- V6架构中预留 `NewsSentimentProvider` 接口（抽象类），未来可通过LLM API接入
- **不要实现**——维护成本和收益不成正比，等需要时再实现具体Provider

    Evidence Engine

    NewsSentimentProvider（LLM接口，预留不实现）

## 五、V6 开发启示与路线图建议

### 5.1 核心架构概念：Evidence Engine（替代"ML Confidence"的命名）

V6最大的架构升级不是引入ML，而是将 Confidence 的来源**多元化**。建议将原来的单一Confidence重新设计为 **Evidence Engine**：

```
Evidence Engine
├── Rule Confidence      —— V5已有，人工规则打分
├── Replay Confidence    —— V5.1新增，行为历史成功率统计
├── ML Confidence        —— V6新增，机器学习概率输出
└── Probability Calibration —— V6新增，概率校准（确保预测80%时实际≈80%）

                    ↓ 融合（加权/投票/Stacking）

              Final Confidence
```

**命名原则**：不再叫"ML Confidence"，因为Confidence的来源是多元的。Evidence Engine负责聚合所有证据。

### 5.2 调整后的优先级排序

**关键修正**：原报告高估了ML的优先级。V6最大的升级不是ML，而是让系统开始"学习"——从最简单的统计学习开始。

| 版本 | 优先级 | 改进项 | 风险 | 收益 | 理由 |
|:---:|:---:|------|:---:|:---:|------|
| **V5.1** | 🔴 P0 | **Replay Learning**（行为成功率统计） | 低 | 高 | 最低风险、最可解释、立即可落地 |
| **V5.1** | 🔴 P0 | **Time Decay**（观察期置信度衰减） | 低 | 中 | V5明显遗漏——Candidate存续太久会失效 |
| **V5.5** | 🟡 P1 | **EmotionBuilder**（多源数据融合，非局限PCA） | 中 | 高 | 数据驱动情绪，可插拔算法 |
| **V5.5** | 🟡 P1 | **价格+情绪双确认** | 低 | 中 | 论文二验证有效，改动最小 |

### 5.3 V5.1：Replay Learning + Time Decay（最低风险第一步）

#### 5.3.1 Replay Learning（行为成功率统计）

**核心思想**：不需要任何ML模型，只靠统计就能让系统开始"学习"。

```
每次交易完成后，Replay Engine记录：

    Bull + DoubleBottom → Success（+1）
    Bear + DoubleBottom → Failure（-1）
    Range + FalseBreak  → Success（+1）

累积后得到 Behavior Success Table：

    | Regime | Behavior        | Total | Success | Rate  |
    |--------|-----------------|-------|---------|-------|
    | Bull   | DoubleBottom    | 12    | 11      | 91.7% |
    | Bull   | TrendPullback   | 8     | 6       | 75.0% |
    | Bear   | DoubleBottom    | 13    | 5       | 38.5% |
    | Bear   | PanicSell       | 6     | 5       | 83.3% |
    | Range  | FalseBreak      | 9     | 8       | 88.9% |
    | Range  | BreakoutConfirm | 7     | 4       | 57.1% |

然后自动更新 Behavior 的基础分：

    Bull + DoubleBottom → Confidence × 1.15  （91.7% → 加分）
    Bear + DoubleBottom → Confidence × 0.80  （38.5% → 减分）
```

**实现方案**（新增 `behavior_memory.py`）：
1. 维护滑动窗口（最近N=90个交易日）
2. 按 `(Regime, BehaviorType)` 分组统计成功/失败
3. 成功率 > 70% → Confidence × 1.1
4. 成功率 < 40% → Confidence × 0.8
5. 连续3次失败 → Confidence × 0.7（紧急降权）
6. 30日无新样本 → 回归中性（衰减到1.0）
7. 最小样本量=5（冷启动时用Rule Confidence兜底）

**优势**：
- 不需要任何ML模型，纯统计
- 完全可解释（"这个DoubleBottom被降权是因为过去10次在熊市只成功了4次"）
- 与Replay Engine自然衔接
- 这是论文一"ML过滤信号"思想的**最简实现**

#### 5.3.2 Time Decay（观察期置信度衰减）

**V5当前问题**：Candidate在Observation状态超过一定天数后，置信度不再变化，但市场环境已经改变。

```
V5当前：
    Day1: Confidence=40 → Day2: 48 → Day3: 56 → Day4: 56 → Day5: 56 → Day6: 56 ...
    问题：Day6的56分和Day3的56分含义完全不同——市场已经变了

V5.1修正：
    Day1: Confidence=40 → Day2: 48 → Day3: 56 → Day4: 56 → Day5: 56
    Day6: Confidence = 56 - 3(衰减) = 53
    Day7: Confidence = 53 - 3 = 50
    ...
    超过EXPIRY_THRESHOLD=25 → 过期
```

**实现方案**（修改 `event_engine.py` 的 `BehaviorEvent.update()`）：
```python
# 新增参数
OBSERVATION_GRACE_PERIOD = 5      # 前5天不衰减
TIME_DECAY_RATE = 0.05            # 每天衰减5%
TIME_DECAY_MIN_CONFIDENCE = 25    # 衰减到此值以下→过期

# 伪代码
if days_in_observation > OBSERVATION_GRACE_PERIOD:
    decay = confidence * TIME_DECAY_RATE
    confidence -= decay
```

**Time Decay 在 Evidence Engine 中的位置**：
```
Evidence Engine
├── Rule Confidence
├── Replay Confidence
├── ML Confidence
├── Probability Calibration
└── Time Decay（在所有证据之后施加，作为时间惩罚项）
```

### 5.4 V5.5：EmotionBuilder（多源数据融合情绪引擎）

**目标**：用多源市场数据驱动的Emotion Score替代纯价格指标的情绪判定。

**改造范围**：[crowd_psychology.py](file:///d:/windows10桌面/量化/V5.0/crowd_psychology.py#L69-L107) 的 `_determine_target_state()`

**核心架构**——不锁死在PCA：

```python
class EmotionBuilder:
    """
    多源数据融合情绪引擎。
    支持多种后端算法，默认PCA，可切换。
    """
    def __init__(self, method='pca'):
        self.method = method  # 'pca' | 'autoencoder' | 'ica' | 'umap' | 'lightgbm'
        self._scaler = StandardScaler()
        self._model = self._build_model(method)

    def _build_model(self, method):
        if method == 'pca':
            return PCA(n_components=0.85)        # 累积贡献率>85%
        elif method == 'autoencoder':
            return AutoEncoder(latent_dim=1)     # 非线性降维
        elif method == 'ica':
            return FastICA(n_components=1)       # 独立成分
        # ... 未来可扩展

    def build_emotion_score(self, market_data: dict) -> float:
        """
        输入多源市场数据，输出连续 Emotion Score (0-100)
        """
        # 1. 收集特征
        features = [
            market_data['volume'],              # 成交量
            market_data['turnover'],            # 成交额
            market_data['margin_balance_chg'],  # 融资余额变化
            market_data['etf_flow'],            # ETF资金净流入
            market_data['north_bound'],         # 北向资金
            market_data['advance_decline'],     # 涨跌停比
            market_data['new_high_low'],        # 新高新低比
            market_data['put_call_ratio'],      # Put/Call比率
        ]
        # 2. 标准化
        X = self._scaler.fit_transform(features)
        # 3. 降维融合
        score_raw = self._model.fit_transform(X)
        # 4. 缩放到0-100
        return self._scale_to_range(score_raw, 0, 100)

    def map_to_emotion_state(self, score: float) -> Emotion:
        """连续分数 → 离散状态（阈值由历史数据分位数自动确定）"""
        if score < self.percentile_20:   return Emotion.PANIC
        elif score < self.percentile_35: return Emotion.FEAR
        elif score < self.percentile_55: return Emotion.HOPE
        elif score < self.percentile_75: return Emotion.OPTIMISM
        elif score < self.percentile_90: return Emotion.EUPHORIA
        else:                            return Emotion.EXHAUSTION
```

**与现有状态机的兼容**：
- 现有状态机（Panic→Fear→Hope→Optimism→Euphoria→Exhaustion）**保持不变**
- 现有情绪→Behavior映射（[crowd_psychology.py#L172-L222](file:///d:/windows10桌面/量化/V5.0/crowd_psychology.py#L172)）**保持不变**
- **只替换状态判定输入源**——从单维Z-Score规则变为多维市场数据融合
- 每季度滚动重新训练（PCA需要定期更新以跟踪市场结构变化）

### 5.5 V6：ML Confidence（概率输出）

**前提条件**：V5.1和V5.5已完成，积累了足够的训练数据（至少500个带标签的Behavior事件）。

**目标**：Evidence Engine新增ML分支，输出**校准后的概率**。

**训练数据构建**：
- 标签：Event Engine确认的买入信号发出后，N日内是否盈利超过阈值
- 特征：Behavior类型、Regime、Emotion状态、所有evidence标记、Reward/Risk分数、技术指标
- 关键特征：**必须包含 Regime 和 Emotion**，让ML学习行为在不同环境下的条件概率

```python
# V6 Evidence Engine 的完整融合逻辑
class EvidenceEngine:
    def compute_final_confidence(self, event, market_context):
        rule_conf = self.rule_engine.evaluate(event)         # V5原有
        replay_conf = self.replay_engine.get_success_rate(   # V5.1新增
            event.behavior_type, market_context.regime
        )
        ml_prob = self.ml_model.predict_proba(event.features) # V6新增
        ml_prob_calibrated = self.calibrator.calibrate(ml_prob) # 概率校准

        # 加权融合（权重可自适应调整）
        final = (
            rule_conf * 0.30 +
            replay_conf * 0.25 +
            ml_prob_calibrated * 0.35 +
            market_context.emotion_bonus * 0.10
        )
        # Time Decay
        final *= (1 - self.time_decay(event.days_in_observation))

        return final  # 范围 0-100
```

**Probability Calibration（概率校准）**：
- ML输出的原始概率通常不可靠（预测80%但实际只有60%）
- 使用 Platt Scaling 或 Isotonic Regression 校准
- 校准集：留出最近20%的数据不参与训练，专门用于校准

### 5.8 风险提示

1. **Replay Learning 的冷启动问题**：新行为无历史统计，用Rule Confidence兜底，最小样本量=5。

2. **Time Decay 的速率校准**：衰减过快会导致有效信号被误杀，过慢则失去意义。建议初始 `TIME_DECAY_RATE=0.05`，通过A/B测试校准。

3. **EmotionBuilder 的数据源可用性**：融资余额、北向资金等数据可能有延迟（T+1），需处理缺失值。

4. **ML的过拟合风险**：论文一的RF在疫情后预测误差明显增大（MAPE从10%升到18%），说明ML模型在分布外数据上会退化。V6必须做**滚动窗口交叉验证**，而非静态训练/测试集划分。

5. **可解释性保障**：V5的Replay Engine（[replay_engine.py](file:///d:/windows10桌面/量化/V5.0/replay_engine.py)）提供每笔交易的理由。当Evidence Engine融合了ML概率后，必须用SHAP/LIME解释ML的预测，在Replay输出中展示各证据来源的贡献。

6. **复杂度控制**：每个新模块必须有独立的A/B测试证明其对最终PnL的正向贡献。V6不应为了ML而ML。
